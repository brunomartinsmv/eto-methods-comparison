# Legacy outputs

This repository keeps some historical outputs under `outputs/**/legacy/` for
auditability and comparison with earlier exploratory notebooks. These files are
not the official result set for the preprint.

## Official outputs for the preprint

Use the files generated by the current CLI pipeline outside any `legacy/`
directory:

- `outputs/tables/{site}_daily_metrics.csv`
- `outputs/tables/{site}_monthly_metrics.csv`
- `outputs/results/{site}_rolling_7d.csv`
- `outputs/results/{site}_monthly_totals.csv`
- `outputs/figures/{site}/{site}_*.png`
- `outputs/reports/{site}_data_quality.csv`

For the current study, `{site}` is `manaus` or `piracicaba`.

## What counts as legacy

Legacy outputs are files under:

- `outputs/tables/legacy/`
- `outputs/results/legacy/`
- `outputs/figures/legacy/`

They may come from older notebooks, exploratory calibration attempts, previous
filename conventions, or manual export workflows. They were retained because
they can help audit the development history, but they should not be cited as
the primary results of the preprint unless a manuscript section explicitly says
so.

The historical `rolling7d` filename is treated as a legacy convention. Current
CLI outputs use `rolling_7d`.

## How to use legacy files

Use legacy files only for:

- comparing historical exploratory outputs with the current pipeline;
- investigating differences between notebook-era and CLI-era calculations;
- preserving traceability for earlier figures or tables.

Do not use legacy files as:

- the main source for reported RMSE, MAE, MBE, R2, or Willmott's d;
- the main source for preprint figures;
- inputs to the current CLI pipeline.

No legacy output was deleted during repository curation. Keeping them in
`legacy/` directories avoids breaking history while making the official result
set clear to external readers.
